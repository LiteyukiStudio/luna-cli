# AI 助手

AI 助手领域用于读取和管理当前用户自己的会话、轮次、运行、审批以及待处理界面动作。
先动态发现当前 CLI 与服务端共同支持的命令：

`luna help catalog category=ai-assistant limit=100 output=json interactive=false agent=true`

执行前再读取目标命令的完整契约：

`luna help command path=<category.tool> output=json interactive=false agent=true`

## 边界

- 会话、轮次和运行都按当前登录用户隔离；不要尝试读取或修改其他用户的数据。
- 创建新轮次、恢复输入、批准工具调用和取消运行都属于有状态操作。执行前读取会话与运行的当前状态，执行后重新读取对应运行验证终态。
- 流式事件接口用于回放和跟随持久化事件。必须限制运行 ID、等待时间和事件数量；断线后按服务端游标恢复，不自行猜测丢失事件。
- 待处理界面动作面向发起会话的浏览器客户端。CLI 可以读取和诊断，但只有实际完成对应界面导航或交互后才能确认动作。
- Provider 测试只用于管理员验证配置连通性，不代表模型调用、工具授权和完整会话链路都已可用。

## 内部协议

机器目录中的 `ai-assistant-internal` 是 API 与 Agent 之间的委派、策略校验和工具执行协议，
不是用户或外部 Agent 的操作入口。不得直接调用这些命令，也不得构造内部密钥、Actor Grant
或短期委派凭据绕过正常的 `ai-assistant` 会话流程。

## 建议流程

1. 读取 AI 能力状态，确认助手已启用且 Provider 可用。
2. 查找或创建当前用户会话。
3. 创建轮次并启动运行；保存返回的会话、轮次和运行 ID。
4. 通过运行详情或事件流观察进度；需要用户输入、审批或 MFA 时停止自动推进。
5. 用户明确完成所需动作后，通过对应公开命令恢复运行。
6. 读取运行终态和时间线，区分回复、思考摘要、工具调用、错误和界面动作。

删除会话是真删除。执行前必须向用户说明会同时删除该会话的轮次、运行和持久化事件，取得
针对目标会话的明确确认后再执行，并在删除后验证会话已不可读取。
